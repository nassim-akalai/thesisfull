\renewcommand{\abstractname}{Zusammenfassung}
\begin{abstract}
	\addchaptertocentry{\abstractname} % Add the abstract to the table of contents

	Diese Arbeit untersucht, wie sich verschiedene Konfigurationen des
	Echtzeitbetriebssystems Zephyr auf dessen Laufzeitverhalten und
	Speicherbedarf auf ressourcenbeschr\"ankter Hardware auswirken. Als
	Zielplattform dient das nRF52840 Development Kit mit einem
	Arm-Cortex-M4F-Prozessor. Verglichen werden eine Minimal-Konfiguration, eine
	darauf aufbauende Konfiguration mit aktiviertem Logging-Subsystem und eine
	IoT-Konfiguration mit OpenThread, CoAP und DTLS.

	Zur reproduzierbaren Leistungsbewertung werden Kontextwechsel-Latenz,
	Interrupt-Latenz, Timer-Jitter, Heap-Allokationsgeschwindigkeit,
	Heap-Fragmentierung und der statische RAM- und ROM-Bedarf untersucht. Kurze
	Laufzeitvorg\"ange werden mit dem DWT-Zyklenz\"ahler erfasst, w\"ahrend f\"ur
	die periodische Timer-Messung der RTC-basierte Systemtimer benutzt wird.
	Minimum, Maximum, Mittelwert und Stichprobenstandardabweichung werden mit dem
	Welford-Algorithmus laufend berechnet. Getrennte Firmware-Abbilder f\"ur jede
	Kombination aus Konfiguration und Benchmark begrenzen dabei die gegenseitige
	Beeinflussung der Messungen.

	Die entwickelte Messumgebung stellt ein nachvollziehbares Verfahren bereit,
	mit dem sich der Einfluss von ausgew\"ahlten Zephyr-Subsystemen auf derselben
	Hardwareplattform vergleichen l\"asst. Dar\"uber hinaus demonstriert eine
	praxisnahe Sensoranwendung die Verwendung von CoAP \"uber DTLS und einen
	Firmware-Aktualisierungspfad mit MCUboot und MCUmgr.
\end{abstract}

\begin{otherlanguage}{english}
\renewcommand{\abstractname}{Abstract}
\begin{abstract}
	\addchaptertocentry{\abstractname} % Add the abstract to the table of contents

	This thesis investigates how different configurations of the Zephyr
	real-time operating system affect runtime behavior and memory requirements
	on resource-constrained hardware. The target platform is the nRF52840
	Development Kit with an Arm Cortex-M4F processor. Three configurations are
	compared: a minimal configuration, a configuration derived from it with the
	logging subsystem enabled, and an IoT configuration which implements
	OpenThread, CoAP, and DTLS.

	The reproducible performance evaluation covers context-switch latency,
	interrupt latency, timer jitter, heap allocation time, heap fragmentation
	and static RAM and ROM usage. Short runtime operations are measured using
	the DWT cycle counter, while periodic timer measurements use the RTC-based
	system timer. Minimum, maximum, mean, and sample standard deviation are
	calculated online using Welford's algorithm. Separate firmware images for
	every combination of configuration and benchmark limit interference between
	measurements.

	The resulting measurement environment provides a traceable method for
	comparing the impact of selected Zephyr subsystems on the same hardware
	platform. In addition, a practical sensor application demonstrates CoAP over
	DTLS and a firmware update path based on MCUboot and MCUmgr.
\end{abstract}
\end{otherlanguage}
